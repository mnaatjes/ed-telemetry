# Repository Research: ed-scout Architectural Implications for ed-telemetry

## 1. Diagnostic: Comparative Architectural Synthesis

Analyzing `joncage/ed-scout` provides a critical reference point: it is a modern, lightweight Python application attempting the exact same low-level file detection and journal ingestion goals as `ed-telemetry`. Its architectural compromises and production workarounds provide concrete lessons.

## 2. Theory: Comparing Watcher Architectures

| Design Dimension | `joncage/ed-scout` | `ed-telemetry` (ADRs 0006–0009) | Architectural Superiority |
| :--- | :--- | :--- | :--- |
| **Directory Discovery** | Hardcoded Windows HKCU GUID + Steam Linux compatdata path `359320` | Injectable multi-strategy `PathDiscoverer` (Config $\to$ Env $\to$ System Known Folders $\to$ Steam $\to$ Fallback) | **`ed-telemetry`**: Resilient against custom Wine prefixes, Proton drives, and non-Steam installs. |
| **Journal Sorting & Selection** | Lexicographical string sort (`sorted(journals)[-1]`) | Composite sort key: `(parsed_timestamp, part_int, mtime_int)` | **`ed-telemetry`**: Immune to string padding anomalies and clock skew across multi-part sessions. |
| **Stream Tailing & Offset** | Negative relative seek from end: `seek(-size_diff, SEEK_END)` | Monotonic absolute offset tracking: `seek(last_byte_offset, SEEK_SET)` | **`ed-telemetry`**: Eliminates race condition skips and crashes on file rotation/truncation. |
| **Watcher Reactor** | `watchdog` Observer with separate 100ms `FileSystemUpdatePrompter` thread | Hybrid Reactor: OS inotify/ReadDirectoryChanges with 0.5s/1.0s timeout ticker | **`ed-telemetry`**: Solves Linux inotify notification loss cleanly without hammering CPU with unthrottled stat threads. |
| **Snapshot Reading** | Single-shot open with 0-byte check; uncaught crash on partial JSON | Atomic whole-read with 20ms debounce backoff + structural boundary checks (`{...}`) | **`ed-telemetry`**: 100% resilient against game engine in-place truncation races. |
| **Freshness Deduplication** | None; re-reads and re-parses on every event notification | Serialized `SnapshotFreshnessTracker` utilizing 64-bit BLAKE2b byte hashes | **`ed-telemetry`**: Zero unneeded JSON parsing or memory allocations on duplicate polling ticks. |

## 3. Analysis: Key Production Lessons Learned

### Lesson 1: Standalone inotify Observers Are Inadequate on Linux/Wine/Proton
`ed-scout`'s skipped unit test (`@pytest.mark.skip(reason="unreliable on linux")`) and its resort to `FileSystemUpdatePrompter.py` confirm that Linux file events generated by Proton/Wine emulated I/O frequently fail to trigger kernel inotify events consistently.
* **Direct Validation:** This directly validates ADR 0009's decision to mandate a hybrid reactor where a 0.5s / 1.0s polling heartbeat complements filesystem notifications.

### Lesson 2: Seek Arithmetic Must Never Use `SEEK_END` for Append Tailing
Using `seek(-size_diff, SEEK_END)` assumes a static file size between `stat()` and `read()`. In live game situations where high-frequency events (e.g. combat scans) write dozens of lines within a millisecond, negative `SEEK_END` arithmetic drops records or raises `OSError: Invalid argument`.
* **Direct Validation:** Confirms ADR 0008's requirement for absolute forward tracking: `f.seek(state.offset, os.SEEK_SET)`.

### Lesson 3: Decoupling the Core Engine via Messaging
`ed-scout`'s cleanest architectural decision was isolating `EDScoutCore` as a headless Python package and communicating with the UI via ZeroMQ.
* **Direct Validation:** Confirms that `ed-telemetry` must remain an independent, headless library with zero UI dependencies, allowing it to be consumed interchangeably by CLIs, TUIs, background daemons, or web backends.

## 4. Remediation: Concrete Deliverables for Subsequent Disciplines

1. **Adopt Proton Path Resolution Fallback:** Incorporate the Steam compatdata `359320/pfx/drive_c` search heuristic discovered in `SavedGamesLocator.py` into `ed-telemetry`'s `LinuxPathDiscoverer`.
2. **Incorporate Fast Writes Test Fixtures:** Adapt test patterns from `ed-scout/ExampleData/` (e.g. `FastWritesOnStartup.log`) into `ed-telemetry`'s integration test suite to verify burst ingestion during game session launch.
