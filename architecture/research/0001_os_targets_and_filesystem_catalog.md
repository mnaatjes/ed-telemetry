# Platform Research 0001: OS Targets, Journal Filesystem Catalog, and Ingestion Mechanics

## 1. Overview and Problem Statement

To implement robust operating system path discovery (`packages/ed_watcher.discovery`) and file ingestion in `ed-telemetry`, we require an empirically verified catalog of:
1. Target Operating Systems capable of running the Elite Dangerous client.
2. Default filesystem path formulations across native and compatibility-layer environments.
3. The complete taxonomy of files generated by the Frontier Developments client (append logs vs. atomic point-in-time snapshots).
4. Low-level file access and locking semantics (file sharing, buffering, character encoding).

This document serves as the canonical knowledge base and Single Source of Truth (SSoT) for empirical platform facts gathered from official documentation, community reference standards, and production codebase audits.

---

## 2. Target Operating Systems

Elite Dangerous is a closed-source Windows 64-bit application (DirectX 11). While Frontier Developments does not provide a native Linux build, community compatibility environments and Valve's Proton have made Linux (particularly the Steam Deck) an officially recognized tier for running the client.

| Operating System Environment | Execution Mechanism | Frontier Support Level | Target Viability for `ed-telemetry` |
| :--- | :--- | :--- | :--- |
| **Windows 10 / 11 (64-bit)** | Native Win32 / NT Kernel | Official / Primary | **Tier 1 (Primary)** |
| **Linux (Steam Play / Proton)** | Valve Proton compatibility layer via Steam | Community / Proton Verified | **Tier 1 (Primary)** |
| **SteamOS (Steam Deck)** | Custom Proton environment on Arch Linux base | Steam Deck Playable | **Tier 1 (Primary)** |
| **Linux (Standalone Wine / Lutris)** | Wine / DXVK running Frontier Launcher / Epic Games | Unofficial Community | **Tier 2 (Secondary)** |
| **macOS** | Dropped by Frontier in 2018 (v3.3 Beyond) | Unsupported | **Out of Scope** |
| **Consoles (PS4, Xbox One)** | Dropped by Frontier in 2022 (Legacy Galaxy only) | Unsupported | **Out of Scope** |

## 3. Filesystem Path Formulations by OS

The Elite Dangerous client delegates user state storage to the standard Windows user profile directory. Under compatibility environments (Proton / Wine), the game runs inside an isolated Windows virtual prefix where Windows paths map onto host POSIX paths.

### 3.1 Native Microsoft Windows

On Windows, the game client uses the Windows Shell Known Folder API (`FOLDERID_SavedGames`) to locate user game saves.

* **Standard Windows Path:**
  ```text
  %USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous\
  ```
* **Expanded Typical Absolute Path:**
  ```text
  C:\Users\<Username>\Saved Games\Frontier Developments\Elite Dangerous\
  ```
* **OS Environment Marker / Discovery Strategy:**
  - Resolved dynamically via Win32 Shell API: `FOLDERID_SavedGames` (`{4C5C32FF-BB9D-43b0-B5B4-2D780DDF04E3}`).
  - Fallback via Windows Environment Variable: `%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous`.
  - Windows Registry Key: `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders` under `{4C5C32FF-BB9D-43b0-B5B4-2D780DDF04E3}`.

### 3.2 Linux via Steam Play / Proton & Steam Deck

Steam installs Windows games inside dedicated Proton prefixes (`compatdata/<app_id>/pfx`). For Elite Dangerous, the official Steam App ID is **`359320`**.

* **Standard Default Proton Path:**
  ```text
  ~/.steam/steam/steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite Dangerous/
  ```
* **Alternate Common Steam Paths (Debian/Ubuntu/Arch):**
  - Standard Steam: `~/.local/share/Steam/steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite Dangerous/`
  - Flatpak Steam: `~/.var/app/com.valvesoftware.Steam/.steam/steam/steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite Dangerous/`
  - Custom Steam Library: `<custom-library-path>/steamapps/compatdata/359320/pfx/drive_c/users/steamuser/Saved Games/Frontier Developments/Elite Dangerous/`
* **Discovery Strategy:**
  - Check Steam App ID `359320` across standard library roots (`~/.steam/steam`, `~/.local/share/Steam`, and `libraryfolders.vdf`).
  - Scan for active Wine/Proton username (commonly `steamuser`).

### 3.3 Linux via Standalone Wine / Lutris / Heroic (Epic Games / Frontier Standalone)

For non-Steam installations running under custom Wine prefixes:

* **Wine Prefix Path Pattern:**
  ```text
  <WINEPREFIX>/drive_c/users/<username>/Saved Games/Frontier Developments/Elite Dangerous/
  ```
  *(Example under default Wine: `~/.wine/drive_c/users/<username>/Saved Games/Frontier Developments/Elite Dangerous/`)*
* **Discovery Strategy:**
  - Check environment variable `$WINEPREFIX` if defined.
  - Fallback to operator override (`--journal-dir <PATH>` or `ED_JOURNAL_DIR`).

## 4. Game File Taxonomy and Catalog

The Elite Dangerous client outputs two distinct categories of files within the journal directory:
1. **Rolling Append Streams (`Journal.*.log`):** Continuous chronological event streams written line-by-line as JSON.
2. **Atomic Point-in-Time Snapshots (`*.json`):** Overwritten files representing instant game or station state.

### 4.1 Rolling Append Streams (Journals)

| Filename Pattern | Update Semantics | Buffer Mode | Format | Purpose |
| :--- | :--- | :--- | :--- | :--- |
| `Journal.<timestamp>.<part>.log`<br>*(e.g., `Journal.2026-10-06T184512.01.log`)* | Append-only per session; rolls on client restart or reaching size limit (~100 MB). | Line-buffered UTF-8; flushed on discrete events. | Line-delimited JSON (`.jsonl`) | Primary event stream recording all player travel, combat, trade, engineering, and lifecycle events. |

### 4.2 Atomic Point-in-Time Snapshots

Snapshot files are periodically overwritten or generated on specific UI/docking interactions. Ingestion engines must treat these as volatile state snapshots.

| Filename | Update Trigger & Frequency | Update Mode | Payload Schema | Purpose |
| :--- | :--- | :--- | :--- | :--- |
| **`Status.json`** | Continuous cockpit/on-foot polling (every 1–2 seconds or on flag change). | Full file atomic overwrite | Single JSON object with bitmask flags, pips, fuel, firegroup, position | Real-time vehicle & suit HUD state (landing gear, cargo scoop, shields, oxygen). |
| **`Market.json`** | Station docking; opening Commodity Market screen. | Overwritten on market view | JSON object (`event: "Market"`, `Items: [...]`) | Station commodity prices, supply, demand, and buy/sell brackets. |
| **`Outfitting.json`** | Station docking; opening Outfitting screen. | Overwritten on outfitting view | JSON object (`event: "Outfitting"`, `Items: [...]`) | Available ship modules and purchasing prices at station. |
| **`Shipyard.json`** | Station docking; opening Shipyard screen. | Overwritten on shipyard view | JSON object (`event: "Shipyard"`, `PriceList: [...]`) | Available ships for sale and base hull prices at station. |
| **`Cargo.json`** | Cargo hold inventory changes (scooping, jettison, trading, refining). | Overwritten on cargo change | JSON object (`event: "Cargo"`, `Inventory: [...]`) | Current ship cargo inventory manifests and mission allocations. |
| **`NavRoute.json`** | Plotting or replotting multi-hop galaxy map navigation route. | Overwritten on route plot | JSON object (`event: "NavRoute"`, `Route: [...]`) | Multi-hop hyperspace jump waypoints and star system coordinates. |
| **`Backpack.json`** | *Odyssey only:* On-foot inventory pickup, drop, or consumption. | Overwritten on inventory change | JSON object (`event: "Backpack"`, `Items: [...]`, `Components: [...]`) | On-foot personal inventory (micro-resources, data assets, consumables). |
| **`ShipLocker.json`** | *Odyssey only:* Transferring items between ship/SRV storage and character. | Overwritten on locker change | JSON object (`event: "ShipLocker"`, `Items: [...]`) | Ship/SRV micro-resource and engineering materials storage. |
| **`ModulesInfo.json`** | Ship outfitting modifications; ship swap. | Overwritten on module change | JSON object (`event: "ModuleInfo"`, `Modules: [...]`) | Detailed engineering and modification state of fitted ship modules. |
| **`FCMaterials.json`** | Fleet Carrier bartender / materials market access. | Overwritten on bartender view | JSON object (`event: "FCMaterials"`, `Items: [...]`) | Fleet carrier personal micro-resource pricing and stock levels. |

## 5. File Access, Locking, and Ingestion Mechanics

Because Elite Dangerous writes to these files concurrently while third-party readers inspect them, naive file I/O causes file-lock contention, crash loops, or `JSONDecodeError` on partial writes.

### 5.1 Concurrency and File Sharing Semantics
* **Windows File Locking:**
  - The game opens `Journal.*.log` files with shared read access (`FILE_SHARE_READ | FILE_SHARE_WRITE`).
  - **Invariant:** Telemetry readers must open journal files with non-exclusive read permissions. In Python, standard `open(file, 'rb')` opens without mandatory locks on POSIX and Win32, but on Windows, explicit sharing flags or unbuffered binary mode (`open(file, 'rb', 0)`) prevents holding lock handles that interfere with Frontier's write flushes.
* **Linux / Proton Inode Behaviors:**
  - Under Proton, Wine maps Windows file locks to Linux kernel advisory locks or Wine server handles.
  - POSIX tailers reading via `inotify` or polling do not block the Wine write thread.
  - Watchdog `inotify` events are reliable on local Linux filesystems, but can miss events across network-mounted filesystems (NFS/CIFS) or specific Wine prefix virtual drives, requiring a hybrid observer/poll fallback.

### 5.2 Atomic Snapshot Overwrite Hazards (Race Conditions)
* **The Partial Write Phenomenon:**
  - Snapshot files (`Market.json`, `NavRoute.json`, `Backpack.json`) are rewritten by the game client using standard file truncation and writes.
  - A watcher responding immediately to a filesystem write event will occasionally read a 0-byte file or an incomplete JSON string before the OS flush completes.
* **Ingestion Remediation Pattern:**
  - All snapshot readers must implement exponential/linear backoff retries (e.g., up to 5 attempts, 10–20ms apart) when encountering empty files or `json.JSONDecodeError`.

### 5.3 Character Encoding
* **Specification:** All Elite Dangerous Journal and Snapshot files are encoded in **UTF-8**.
* **Byte Order Mark (BOM):** Frontier Developments does not prepend a UTF-8 BOM (`\xef\xbb\xbf`) to journal files, but community best practice mandates handling `utf-8-sig` decoding or raw UTF-8 parsing to tolerate edge-case encoding artifacts.
